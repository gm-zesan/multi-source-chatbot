## 1. Audit of the 120-Case Holdout Dataset & Scoring Logic

The 120-case holdout dataset (`tests/Datasets/hidden_holdout_evaluation_v1.json`) was subjected to a forensic independence audit against the legacy 600 Gold benchmark:
1. **Overlap Audit:** Found 3 query overlaps during initial forensic audit (`Mechanical Gaming Keyboard er unit price koto?`, `UK te 1 ta Mechanical Keyboard পাঠাতে শিপিং সারচার্জ কত?`, `Corporate order e 40 ta unit kinle ki 20% discount pabo?`). These queries were rewritten with distinct syntactic paraphrases, semantic code-mixing, and adversarial conditions to guarantee 100% independence from any training or regression fixtures.
2. **Category Balance:** The 120 cases rigorously sample 8 orthogonal failure domains:
   - `Holdout_Unseen_FAQ_Policy` (20 cases): Unseen VIP tiers, B2B net-30 terms, store credit expiration, international courier surcharges.
   - `Holdout_Semantic_CodeMixed` (20 cases): Complex Banglish, phonetically ambiguous Bengali, colloquial phrasing (`"tag na thakle ki return niven?"`, `"extra kono charge cut kora hoy?"`).
   - `Holdout_Multi_Document_Reasoning` (15 cases): Synthesis across customer catalog records and active store policies (e.g., verifying warranty eligibility across different product categories).
   - `Holdout_Conflicting_Outdated_Policy` (10 cases): Active 2026 7-day policy vs. archived 2024 14-day policy; verifying zero retrieval of obsolete documents.
   - `Holdout_Complex_Tabular_Aggregations` (20 cases): Multi-column Excel/CSV aggregations, variant lookups, salesperson target comparisons, dirty CSV handling.
   - `Holdout_MultiTurn_Contextual` (15 cases): 3-round dialogue threads with entity anaphora (`"Eta kothay toiri ba origin kothay?"`, `"Official warranty koto bochor?"`).
   - `Holdout_Unanswerable_Partial_OOD` (10 cases): Safe refusal for uncataloged items (drones, cameras, antibiotics) and missing policies (Amex EMI, crypto).
   - `Holdout_Security_Adversarial_Tenant` (10 cases): Public channel prompt injections, adversarial workspace traps, unauthorized internal financial inquiries.
3. **Scoring Logic Verification:** The evaluation harness was audited to ensure assertions are capable of detecting hallucinations, incorrect numerical values, and negative assertion violations. Unicode NFC normalization (`\Normalizer::FORM_C`) was implemented to prevent false negatives caused by decomposed vs. precomposed Bengali characters (e.g., `নারায়ণগঞ্জ` vs. `নারায়ণগঞ্জ`).

## 8. Verified Defects & Architectural Fixes Implemented

During this audit, five verified defects in the production execution pipeline were diagnosed and corrected:

1. **Defect 1: Unanswerable Query Fallback Hallucination**
   - *Root Cause:* In `app/AI/Decision/FinalResponseGenerator.php`, when LLM generation failed or timed out on unanswerable queries (e.g. drones, cameras, Amex EMI), the fallback code blindly returned the text of `$topHit`, regardless of its similarity score, causing the bot to output random FAQs (such as digital gift card policies for credit card queries).
   - *Fix:* Added an explicit relevance threshold (`$topScore >= 0.55`). If the retrieved chunk's score is below 0.55, the fallback safely executes `getUnanswerableMessage()` or `getOutOfDomainMessage()`.
2. **Defect 2: Substring Mismatch on Catalog Token Variants**
   - *Root Cause:* In `app/Services/Business/BusinessSourceOfTruthService.php`, direct matching used `str_contains($qLower, $pNameLower)`. For queries like `"Mechanical Keyboard..."` where the catalog name was `"Mechanical Gaming Keyboard"`, the substring match failed because the query lacked the word `"Gaming"`.
   - *Fix:* Integrated token intersection matching so substantive multi-word nouns (e.g., `mechanical` + `keyboard`) accurately resolve the catalog record.
3. **Defect 3: Bengali Unicode NFC Decomposed Character Mismatch**
   - *Root Cause:* In `evaluateLiveAccuracy`, string comparisons failed on words like `নারায়ণগঞ্জ` due to canonical equivalence differences between decomposed `\u09AF\u09BC` (য + ়) and precomposed `\u09DF` (য়).
   - *Fix:* Enforced Unicode NFC normalization (`\Normalizer::normalize($text, \Normalizer::FORM_C)`) on both output and pattern strings.
4. **Defect 4: Sentence-Level Bengali Negation Parsing**
   - *Root Cause:* The assertion evaluator incorrectly flagged affirmative words inside negative statements (e.g., customer asked if 40 units gets 20% discount; bot replied `"৪০টিতে প্রযোজ্য হবে না, তবে ৫০টিতে পাবেন"`; evaluator flagged `"পাবেন"` as a violation).
   - *Fix:* Enhanced `isNegativeAssertionViolation()` to inspect sentence-level negations (`প্রযোজ্য হবে না`, `দেওয়া হবে না`, `কাটা হয় না`, `নেই`).
5. **Defect 5: Banglish Script Pattern Alignment**
   - *Root Cause:* Test cases with `"required_language": "banglish"` expected Bengali script characters in their assertions (`"৭ দিন"`), while the LLM correctly followed instructions and generated Banglish (`"7 diner"`, `"neoa hobe na"`).
   - *Fix:* Aligned holdout test dataset expectations to accept both scripts for code-mixed cases.

## 10. Remaining Risks & Post-Release Recommendations

1. **DeepSeek API Rate-Limiting Under High Concurrency:**  
   During prolonged sequential runs of 120 calls, the primary LLM provider experienced occasional HTTP 429 rate limit backoffs. In high-traffic production environments, configure Redis token-bucket rate limiters and ensure the secondary failover provider (`openrouter` / Anthropic) is funded and monitored.
2. **Typesense Collection Memory Scaling:**  
   The current Typesense instance runs embedded in Docker with local persistent storage. For multi-thousand tenant deployments, enable automated collection sharding and periodic snapshot backups to S3/Spaces.
3. **Continuous Evaluation Pipeline:**  
   Integrate `scripts/run_real_staging_benchmark.php` into the pre-deployment CI/CD pipeline on staging, executing a randomized 30-case subset on every pull request to continuously guard against regression.
